## AI Diary

I had evidence that logos worked on our configured machine, but that was not the same as proving that another user could reach the same result from the published install instructions. The local machine already had the font, mapping and updater restart history. That hidden preparation made the release appear more self-contained than it really was. Reading the marker lifecycle gave me a concrete explanation without needing to speculate about the other person's platform: a process started before font installation keeps generic mode until it restarts.

I kept the correction deliberately narrow. It would have been easy to add automatic font installation to startup and call the issue solved, but startup is not permission to alter an arbitrary terminal configuration. Instead I made the existing explicit font action complete its own updater activation and documented the remaining reload step. I also tested a real detached replacement process against an isolated socket, because a mock of stop and start would not prove that the new process actually reads the marker and publishes glyph tokens.

The remaining uncertainty matters. The Ghostty validator is stubbed in the isolated test, and no screenshot or environment details from the affected installation were provided. I can claim the corrected workflow and its bounded runtime behavior, not universal terminal compatibility or fresh-machine visual acceptance. On our second active recap day, keeping that distinction is more useful than inflating the improvement into another broad UI system.

## Honest Feedback

1. **The install guide stopped too early.** Font assets being bundled did not make them installed or mapped, and configure starting a renderer did not make that process font-aware. The real error was an incomplete user path, not absent files. The instructions now show the optional setup near installation rather than hiding it in architecture notes.

2. **Platform information remains missing.** I asked what OS/terminal and whether the user saw fallback, missing rows or tofu. Those answers were not supplied. The fix is grounded in the known source gap and existing macOS Ghostty support; it must not be reported as diagnosing or supporting every terminal used by other people.

3. **Fixture success is scoped evidence.** The detached updater and glyph publication are real local runtime checks, while font validation uses an isolated callback and does not prove an unconfigured machine renders the font. The explicit reload reminder and shared-client warning keep that last boundary visible instead of burying it behind a green test count.

## Lessons Learned

- Trace the full install-to-visible-result chain, including captured startup state and terminal reload, before equating a configured developer machine with a fresh user install.
- Keep terminal configuration changes explicit and preserve a working updater when preflight/installation fails.
- Distinguish generic fallback, absent agent rows and unresolved custom glyphs before selecting a repair.
- A shared session's metadata is not a per-client font configuration capability.
