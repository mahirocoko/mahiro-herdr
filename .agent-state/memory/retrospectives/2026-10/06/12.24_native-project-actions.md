could have reached the project/new-tab outcome earlier. I offered a popup-only

Second, I overtrusted self-consistent fixtures at the transport boundary. The
actual CLI acknowledgement and popup target rules were available in the runtime
and upstream source, but my first implementation did not replay the exact host
contract. Third, the supported terminal interface is not the GUI manager or the
native plus-tab chooser Mahiro ultimately prefers. I must not market the picker

its existing owner, avoiding duplicate submission after errors, preserving
config recovery, and using narrow runtime evidence instead of adding routine
reviewers. The remaining human interaction and color checks are explicitly open.

## Lessons and evidence

- Exit-status success and JSON receipts are separate CLI contracts. Silent
  acknowledgement is accepted only for pane run/tab focus, not inventory/create.
- Popup has no pane ID and targets the active surface; preserve original action
  context in a bounded env payload and revalidate before catalog saves/launch.
- A live config extension must preserve the exact original recovery bytes and
  align the applied snapshot, not silently break uninstall through config drift.
- Manage never runs commands; it validates, confirms, locks and atomically saves
  the project-owned catalog, refusing external edits and symlinks.
- ANSI semantic slots inherit terminal colors. NO_COLOR, dumb terminals and
  redirected output remain plain; exact resolved contrast is not claimed.
- Native GUI plus-tab injection remains unsupported by the inspected plugin
  boundary. Upstream writing was not authorized or performed.

No reference learning was promoted: current owner docs already contain these
decisions, so a second reference note would fail the novelty gate.
